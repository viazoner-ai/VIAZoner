# volonter.by — помоги рядом ❤️

**Платформа волонтёрской помощи в Беларуси: мобильное приложение (PWA) + сайт**

Здесь встречаются те, кому нужна помощь (частные лица и организации), и волонтёры,
которые готовы помогать. Заявки с датами и условиями, отклики волонтёров,
история помощи, отзывы и рейтинг.

</div>

## Что умеет платформа

### 👤 Волонтёр
- ищет заявки **по городу, категории, дате** и ключевым словам;
- откликается на заявку с личным сообщением («готов прийти в субботу…»);
- отменяет отклик, пока автор его не принял;
- ведёт **историю помощи** в личном кабинете: дела, часы, полученные оценки и отзывы;
- формирует **публичный рейтинг**: виден всем в базе волонтёров;
- переписывается с авторами заявок во встроенном чате.

### 🏢 Организация или частное лицо
- регистрируется в роли **организации** или **частного лица**;
- публикует заявку: категория, описание, город, **конкретная дата или «по договорённости»**,
  время, число волонтёров, **условия**, отметка «срочно»;
- видит **все отклики** с сообщениями и контактами волонтёров;
- принимает / отклоняет отклики;
- после оказания помощи ставит **оценку 1–5**, пишет отзыв и указывает часы —
  это идёт в рейтинг волонтёра;
- может **сам написать волонтёру из базы** и позвать на свою заявку;
- закрывает заявку, когда помощь оказана.

### 📱 PWA = мобильное приложение + сайт
Один код работает везде:
- на телефоне — как мобильное приложение (кнопка «Установить приложение»,
  иконка на главном экране, офлайн-кэш);
- на компьютере — как полноценный сайт volonter.by;
- интерфейс адаптивный: на мобильном — нижняя навигация, на десктопе — верхнее меню.

## Технологии

| Слой | Стек |
|---|---|
| Клиент (PWA + сайт) | React 19, TypeScript, Vite, Tailwind CSS, Font Awesome |
| Сервер API | Node.js (встроенный `http`), без внешних зависимостей |
| База данных | SQLite через встроенный `node:sqlite` (файл `server/data/volonterby.db`) |
| PWA | `manifest.webmanifest`, service worker `public/sw.js`, иконки всех размеров |

**Про MySQL.** SQL-схема написана совместимой с MySQL/MariaDB (обычные типы
`INTEGER/TEXT/REAL`). Для выкладки на классический хостинг с Apache + MySQL нужно
только заменить драйвер и `AUTOINCREMENT` → `AUTO_INCREMENT` — структура таблиц не меняется.

## Запуск

Нужен Node.js **22+** (используется встроенный `node:sqlite`).

```bash
# 1. установить зависимости (клиент + сервер)
npm run setup

# 2. терминал 1 — API (порт 8787)
npm run server

# 3. терминал 2 — сайт/PWA (порт 3000, проксирует /api на сервер)
npm run dev
```

Открыть: **http://localhost:3000**

База создаётся и наполняется демо-данными автоматически:

```bash
node server/seed.js          # если база пуста
node server/seed.js --force  # пересоздать с нуля
```

## API (кратко)

Базовый URL: `/api` (в dev проксируется Vite на `http://127.0.0.1:8787`).
Авторизация: заголовок `Authorization: Bearer <token>`.

| Метод и путь | Назначение |
|---|---|
| `POST /api/register`, `/api/login`, `/api/logout` | аккаунты |
| `GET /api/me` | текущий пользователь |
| `GET /api/volunteers?city=&skill=&q=&sort=` | база волонтёров с рейтингом |
| `GET /api/volunteers/:id` | профиль волонтёра + отзывы |
| `GET /api/requests?city=&category=&status=&q=&urgent=` | лента заявок |
| `POST /api/requests` | создать заявку (организация/частное лицо) |
| `GET /api/requests/:id` | заявка + все отклики |
| `POST /api/requests/:id/respond` | отклик волонтёра |
| `PATCH /api/requests/:id` | статус заявки (done/closed/open) |
| `PATCH /api/responses/:id` | accept / decline / finish (с оценкой) / cancel |
| `GET /api/my/requests`, `GET /api/my/responses` | личный кабинет |
| `POST /api/messages`, `GET /api/messages?peer=`, `GET /api/inbox` | чаты |
| `PATCH /api/profile` | обновление профиля |
| `GET /api/stats` | счётчики для главной |

## Продакшен-заметки

1. `npm run build` → статика в `dist/`.
2. Раздать `dist/` любым хостингом (nginx/Apache), API — `node server/server.js`.
3. Домен volonter.by: купить у белорусского регистратора, привязать A-записи, включить HTTPS (Let's Encrypt).
4. Перенос на MySQL/MariaDB — см. комментарий в `server/server.js`.
5. Политика модерации: заявки от организаций стоит подтверждать (проверка УНП),
   а для частных лиц — рекомендации и верификация по телефону.
6. Ограничения для MVP: пароли хранятся хэшем SHA-256 с солью (для продакшена
   заменить на bcrypt/argon2 и добавить восстановление пароля), нет e-mail рассылки.
